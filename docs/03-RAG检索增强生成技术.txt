RAG 检索增强生成技术完全解析

一、什么是 RAG？

RAG（Retrieval-Augmented Generation，检索增强生成）是一种将信息检索与文本生成相结合的技术架构。它的核心思想是：在 LLM 生成回答之前，先从外部知识库中检索相关文档片段，然后将这些片段作为"参考资料"一起送入 LLM，从而显著提高回答的准确性和可靠性。

为什么需要 RAG？因为 LLM 存在三个固有问题：
1. 知识截止日期：训练数据有截止时间，无法回答最新问题
2. 幻觉问题：对于不知道的内容，LLM 可能编造看似合理但错误的答案
3. 领域知识不足：通用 LLM 在专业领域（医疗、法律、金融）的表现不佳

RAG 通过引入外部知识库，同时解决了这三个问题。

二、RAG 的工作流程

一个标准的 RAG 系统包含两个阶段：

【离线阶段（索引构建）】
1. 文档加载：从 PDF、TXT、Markdown、网页等来源读取文档
2. 文本分块：将长文档切分为合适大小的小块（chunk）
3. 向量化：用 Embedding 模型将每个 chunk 转为向量
4. 存储：将向量存入向量数据库（Chroma、Milvus、Pinecone 等）

【在线阶段（问答流程）】
1. 用户提问："什么是 MCP 协议？"
2. Query 向量化：将问题转为向量
3. 相似度检索：在向量库中找到与问题最相似的 K 个文档 chunk
4. 上下文拼接：将检索到的 chunk 内容拼入 Prompt
5. LLM 生成：将拼接好的 Prompt 送入 LLM，生成最终回答

三、Embedding 模型的选择

对于中文 RAG 系统，推荐以下 Embedding 模型：

- BAAI/bge-small-zh-v1.5：轻量级（133MB），适合本地开发，CPU 即可运行
- BAAI/bge-large-zh-v1.5：高质量（1.3GB），适合生产环境
- shibing624/text2vec-base-chinese：中文优化，兼顾语义和效率
- moka-ai/m3e-base：社区热门，在中文 MTEB 榜单表现优秀

选择建议：学习阶段用 bge-small-zh-v1.5（免费、本地、够用），面试项目用 bge-large-zh-v1.5（效果更好）。

四、文档分块策略

分块（Chunking）是 RAG 系统最关键的超参数之一。分块太大，检索精度下降；分块太小，上下文不完整。

常用的分块策略：
- 固定大小分块：chunk_size=1000, overlap=200（最常用）
- 按段落分块：以 \n\n 为分隔符，保持段落完整性
- 按句子分块：以句号为分隔符，适合精细检索
- 语义分块：用模型判断语义边界，效果最好但成本高

分块大小建议：
- 技术文档：chunk_size=500-800
- 长文章/报告：chunk_size=1000-1500
- 对话记录：chunk_size=300-500
- overlap 一般取 chunk_size 的 10%-20%

五、RAG 的评估指标（RAGAS）

如何量化评估 RAG 系统的好坏？RAGAS 提供了四个核心指标：

1. Faithfulness（忠实度）：生成的回答中有多少内容可以在检索到的文档中找到依据。高忠实度意味着低幻觉。

2. Answer Relevancy（答案相关性）：生成的回答与用户问题的相关程度。回答再准确，如果不切题也没有意义。

3. Context Precision（上下文精度）：检索到的文档 chunk 中，有多少是真正有用的。低精度意味着检索了大量无关内容。

4. Context Recall（上下文召回率）：所有相关文档 chunk 中，有多少被成功检索到。低召回意味着遗漏了重要信息。

一个优秀的 RAG 系统应该在这四个指标上都达到 0.8 以上。
